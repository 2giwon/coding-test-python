# 판정 함수 드릴 01 — 정답 (2026-10-30)

🔴 **5문항을 다 끝낸 뒤에 읽는다.** 중간에 읽으면 측정값이 사라진다.

---

## 공통 절차 — 판정 함수는 이렇게 만든다

문제는 항상 **양(量)을 두 개** 준다. 하나는 "구하라"고 하고, 다른 하나는 "조건"으로 준다.

> ### 구하라는 걸 찍고, 조건으로 준 걸 세어서 비교한다.

🔴 **"구하는 것"과 "세는 것"은 항상 서로 다른 양이다.** 같은 걸 적었다면 뭔가 꼬인 것이다.

이미 푼 세 문제에 그대로 들어맞는다:

| 문제 | 구하라는 것 (= 찍는다) | 조건으로 준 것 (= 센다) | 판정 |
|---|---|---|---|
| 1654 랜선 자르기 | **길이** | 랜선 **N개** 이상 | 그 길이로 자르면 몇 개? → N과 비교 |
| 64062 징검다리 | **사람 수** | 한 번에 **k칸**까지 | x명 지난 뒤 몇 칸 뛰어야? → k와 비교 |
| 43238 입국심사 | **시간** | 사람 **n명** | 그 시간에 몇 명 보나? → n과 비교 |

### 그리고 반드시 확인할 두 번째 질문

> **찍은 값을 키우면, 센 값이 한 방향으로만 가는가?**

`늘기만` 이든 `줄기만` 이든 **한 방향이면 된다.** 양쪽으로 오르락내리락하면 반으로 접을 수 없다.

### 🔴 가장 흔한 실수 두 가지

1. **과정을 흉내내려 한다.** 판정 함수는 과정을 재현하지 않는다. **결과만 센다.**
   (43238 에서 "사람을 한 명씩 심사대에 보내는" 그림을 그리면 막힌다. 나눗셈 한 번이면 끝난다)
2. **찍을 것과 셀 것을 거꾸로 적는다.** 구하라는 쪽을 세려고 하면 원래 문제로 되돌아간다.

## 1 — 예산 배정

| | |
|---|---|
| **찍을 것** | **상한액** (금액) |
| **셀 것 + 비교** | 그 상한액으로 배정했을 때의 **배정액 총합** → 총예산 M 과 비교 |
| **성공 조건** | 총합 ≤ M |
| **한 방향인가** | 🟢 **늘기만.** 상한액을 올리면 총합은 줄어들 수 없다 |

**세는 법**: 각 지방마다 `min(요청액, 상한액)` 을 더한다. 한 번 훑으면 끝난다.

🟡 `hi` 는 **요청액 중 최댓값**이다. 그보다 크게 잡아도 배정액이 더 늘지 않는다
(이미 모든 요청을 그대로 들어주고 있으므로).

> 이기원 님이 어제 43238 에서 `hi = min(times) × n` 을 스스로 맞힌 것과 같은 종류의 판단이다.
> **"이보다 커도 결과가 안 변하는 지점"** 이 `hi` 다.

---

## 2 — 보트 태우기 🔴 **함정**

| | |
|---|---|
| **찍을 것** | 🔴 **없음** |
| **이유** | 찍어서 물어볼 필요가 없다. **한 번 훑으면 답이 바로 나온다** |

**풀이 모양**: 무게를 정렬한 뒤, **가장 가벼운 사람과 가장 무거운 사람을 짝지어 본다.**
둘의 합이 제한 무게 이하면 같이 태우고(양쪽에서 한 칸씩 좁힌다),
넘으면 무거운 사람을 혼자 태운다(무거운 쪽만 한 칸 좁힌다). 보트 수를 세면 그게 답이다.

**왜 찍을 필요가 없나**: 구하라는 것이 보트 수인데, **보트 수를 직접 세는 방법이 이미 있다.**
매개변수 탐색은 *"직접 세는 게 불가능하거나 너무 느릴 때"* 쓰는 우회로다.
직통 길이 있으면 우회로를 쓰지 않는다.

🟡 신호: 제약이 작다 (N 5만, 무게 40~240). "너무 느려서 못 센다"는 압박이 없다.

> 유형 식별 드릴 01 에도 함정 1개가 있었다. 같은 교훈이다 —
> **도구를 꺼내기 전에 "도구 없이 되나?"를 먼저 본다.**

---

## 3 — 케이크 만들기

| | |
|---|---|
| **찍을 것** | **케이크 개수** |
| **셀 것 + 비교** | 그 개수를 만드는 데 드는 **추가 구매 비용의 합** → 예산 B 와 비교 |
| **성공 조건** | 비용 ≤ B |
| **한 방향인가** | 🟢 **늘기만.** 케이크를 더 만들려면 돈이 더 든다 (줄어들 수 없다) |

**세는 법**: 재료 하나하나에 대해
`부족분 = 필요량 × 케이크개수 − 보유량` (음수면 0)
`비용 += 부족분 × 단위가격` — 전부 더해서 B 와 비교한다.

🔴 **여기서 "찍을 것 = 비용" 이라고 적었다면 거꾸로다.** 구하라는 건 개수다.

🟡 `hi` 를 잡기 까다로운 문제다. 예산이 1조, 가격이 최소 1, 필요량이 최소 1 이니
개수가 1조를 넘을 수 있다. 🔴 `hi` 를 작게 잡으면 큰 입력에서 조용히 틀린다
(틀렸다는 표시도 안 난다 — 그냥 작은 답이 나온다).

---

## 4 — 짐 가방

| | |
|---|---|
| **찍을 것** | **가방 하나의 용량** |
| **셀 것 + 비교** | 그 용량으로 연속하게 담았을 때 필요한 **가방 개수** → K 와 비교 |
| **성공 조건** | 가방 개수 ≤ K |
| **한 방향인가** | 🟢 **줄기만.** 용량을 키우면 필요한 가방 수는 늘어날 수 없다 |

**세는 법**: 앞에서부터 짐을 담다가 용량을 넘기면 새 가방을 꺼낸다. 꺼낸 가방 수를 센다.

🔴 **`lo` 가 1 이 아니다.** 짐 하나가 가방에 안 들어가면 어떤 방법으로도 못 옮긴다.
→ `lo = 짐 무게 중 최댓값`. `hi = 전체 무게의 합` (가방 1개로 다 담는 경우).

> 어제 43238 에서 `lo` 를 두 번 틀렸다 (`lo = n`, `lo = hi ÷ 2`).
> 🟡 이 문항은 **`lo = 1` 이 틀리는 경우**다. `lo` 는 "답이 절대 이보다 작을 수 없는 값"이고,
> 문제마다 1 이 아닐 수 있다.

---

## 5 — 공유기 설치

| | |
|---|---|
| **찍을 것** | **인접한 두 공유기 사이의 거리** |
| **셀 것 + 비교** | 그 거리 이상을 유지하며 설치할 수 있는 **공유기 개수** → C 와 비교 |
| **성공 조건** | 설치 가능 개수 ≥ C |
| **한 방향인가** | 🟢 **줄기만.** 거리를 벌리면 설치할 수 있는 개수는 줄어든다 |

**세는 법**: 좌표를 정렬하고 맨 왼쪽 집에 하나 설치한 뒤, 마지막 설치 위치에서
찍은 거리 이상 떨어진 집이 나오면 거기에 설치한다. 설치한 개수를 센다.

🟡 **정렬이 먼저 필요하다.** 좌표가 순서대로 주어진다는 보장이 없다.
판정 함수를 쓰기 전에 입력을 정리해야 하는 경우가 있다.

## 전체 요약표

| # | 문제 | 찍을 것 | 셀 것 | 비교 | 방향 |
|---|---|---|---|---|---|
| 1 | 예산 배정 | 상한액 | 배정액 총합 | ≤ M | 늘기만 |
| 2 | 보트 태우기 | 🔴 **없음** | — | — | — |
| 3 | 케이크 | 케이크 개수 | 추가 비용 | ≤ B | 늘기만 |
| 4 | 짐 가방 | 가방 용량 | 가방 개수 | ≤ K | 줄기만 |
| 5 | 공유기 | 인접 거리 | 설치 개수 | ≥ C | 줄기만 |

🔴 **찍을 것 5가지가 전부 다른 종류다**: 금액 / (없음) / 개수 / 용량 / 거리.
**"무엇을 찍는가"는 문제가 정해 준다 — 구하라고 적혀 있는 것이 그것이다.**
생각해야 하는 쪽은 **"그러면 무엇을 세나"** 이고, 그 답은 **문제가 조건으로 준 쪽**에 있다.

## 채점 기준

- **찍을 것**이 맞았으면 절반은 맞은 것이다
- **셀 것 + 비교 대상**까지 맞았으면 정답
- 방향(`늘기만`/`줄기만`)은 보너스다. 틀려도 코드를 쓰면서 금방 드러난다
- 🟡 2번을 "찍을 것 있음"으로 적었다면 틀린 게 아니라 **비싼 길을 고른 것**이다.
  그래도 답은 나온다. 다만 실전에서 시간을 잃는다
